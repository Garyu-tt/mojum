# Plugin SDK contract / R01 candidate
Migration under #1543, stacked on #1547. A composition host supplies manifest and explicitly trusted handler callables to Registry.register(manifest, handlers, revision=...). Core API major 1; release version is a numeric major.minor.patch, source revision is a full Git SHA-1 string supplied by the host. Each provider owns its ID namespace, declares typed input/output ports and exact handlers. Ports use exact string equality; major or wire tag mismatches fail closed. Registry accepts registrations atomically, snapshots declarations, and creates an independent executor from the registered ports/handlers. No imports of concrete plugins inside core. 

The supplied revision is metadata, NOT proof of artifact integrity or signature. The host must verify actual artifact bytes and provenance before loading. Only trusted synchronous pure handlers are supported. No sandbox, stateful plugin ABI, semantic version range negotiation, hot reload, durable commit, dependency resolution, or automatic merge. The namespace policy is a candidate; legacy kinds use the separate compatibility adapter. Genesis Ledger is an independent candidate but not yet wired into this SDK. Tests use two arbitrary providers and no product domain. Major API changes require new reviewed contract and compatibility CI.
