# Legacy simulation checkpoint migration
Stacked on #1546 under #1543. The six domain fixture handlers and legacy wire format live in a compatibility adapter outside mojum_core, not in the core. The adapter reads and writes mojum.sim-checkpoint/0.1 with the original canonical digest, verifies identity and reproduces every staged episode using a scratch executor before swapping state. Bidirectional tests cover zero, one and two episode sinks, tampering and late failures. 
Scope: synthetic sim.py only, not Aquarium SQLite, real organism state or arbitrary plugin persistence. New explicit replay cap 10,000 ticks, including zero-sink history; longer legacy checkpoints are rejected pending a separate reviewed strategy. Executor JSON budgets also apply. In-memory only; not a durable transaction, hostile Python sandbox or authenticated signature. Whole snapshot admission size belongs to the caller. Independent review and expanded parity tests remain required.
## Consolidated review correction
The legacy fixture adapter now serializes step, snapshot capture, restore and public state reads with one state lock. A step at MAX_REPLAY_TICKS is rejected before advancing, including zero-sink graphs. This deliberately limits this migration adapter to 10,000 ticks; it does not implement long-running simulation checkpoint compaction, generic plugin state, persistence or an overall hostile-input memory budget. Existing longer legacy checkpoints are still outside the supported replay window. The caller must not mutate restore inputs concurrently. The legacy format is unchanged.
