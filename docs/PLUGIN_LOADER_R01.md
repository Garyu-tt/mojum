# Release lock and trusted artifact loader / R01 candidate
Stacked on #1548, migration under #1543. The composition host supplies an independently trusted lock with plugin ID, exact release version, Git revision metadata, manifest SHA-256 and source SHA-256. The loader accepts bounded immutable bytes for a single source file and JSON manifest. No branch checkout, network access, path resolution or automatic discovery. All bundle digests, manifests and Python syntax are checked before any provider code runs. A fresh Registry is returned only after all actual handler declarations pass. A previous trusted lock and its exact artifacts can be loaded separately; this is not live-state rollback.

Trust boundary: Python exec and imports run with full host permissions. Only independently reviewed, trusted source may be admitted; a hash is not a signature and Git revision metadata is not proof of source provenance. Imported dependencies are not pinned by this candidate, so reproducibility is conditional on a fixed trusted runtime and self-contained providers. Registration failures cannot undo module-level side effects. No untrusted plugin execution, persistent release catalog, package loader, automatic merge, or deployment integration is provided. The host must establish release trust and enforce isolation before running third-party code. CI tests are synthetic; the GENESIS Ledger integration is still pending.

## Consolidated review correction
Each trusted source executes in a unique temporary ModuleType registered in sys.modules during definition and registration, supporting dataclass definition-time introspection. The registration is removed on success or failure; handler globals stay alive through function references. This is deliberately not a general importable module or package lifecycle: runtime lookup by generated module name, class pickling and annotation resolution requiring that module entry are not supported. No stable module identity is promised. The generated name is runtime-private, not a wire identifier. Providers must keep module-level effects outside their contract. Rollback tests now execute both the old and new artifacts after loading the old lock again.
